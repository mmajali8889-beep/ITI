# تدريب المستخدمين حسب الأدوار (30.3)

هذه المادة لتدريب موظفي المستشفى الأولى قبل التجربة التشغيلية (30.4). كل دور له دليل قصير بتمارين على مرضى وهميين، وفي آخره اختبار عملي يوقّعه المدرّب.

## بيئة التدريب

- **العنوان:** بيئة منفصلة عن الإنتاج وعن staging (على هذا الجهاز: `https://training.localhost:8449`).
- **البيانات:** وهمية بالكامل. مرضى التمارين أرقامهم الوطنية تبدأ بـ `999`، ولا يجوز إدخال أي مريض حقيقي.
- **الحسابات:** حساب لكل دور، على شكل `train.<الدور>` (مثل `train.nurse` و`train.doctor`)، بكلمة مرور مشتركة. يستلمها المدرّب من ورقة الحسابات التي يكتبها سكربت التهيئة، ولا تُستخدم هذه الحسابات خارج بيئة التدريب.
- **إعادة التهيئة:** يعيد قسم تقنية المعلومات البيئة إلى حالتها الأولى باستعادة نسخة احتياطية، ثم تشغيل سكربت التهيئة (انظر "للمسؤول التقني" أدناه).

## مرضى التمارين

| | المريض | التمرين |
|---|---|---|
| A | سارة التدريب | زيارة عيادة مع مختبر وأشعة، دفع نقدي (التمرين الجماعي) |
| B | خالد التدريب | مريض تأمين: الأهلية، المطالبة، نتيجة المطالبة |
| C | ليلى التدريب (طفلة) | حساسية من البنسلين: تنبيه الحساسية عند الوصف |
| D | يوسف التدريب | وصول للطوارئ، فرز، ثم تنويم في سرير |
| E | منى التدريب | الصيدلية: تدقيق وصفة وصرفها |
| F | عمر التدريب | السجلات الطبية: نواقص، إغلاق، قفل، تعديل |
| G | هدى التدريب | بوابة المريض: إنشاء حساب ودخول المريض |
| H | سامي التدريب | موعد محجوز: تسجيل الوصول في الاستقبال |

## خطة الجلسات

1. **جلسة تعريفية مشتركة** (30 دقيقة لكل الأدوار):
   - الدخول، واختيار المستشفى، والقائمة الجانبية.
   - البحث عن مريض في **Patient Registry**.
   - شريط المريض والتنبيهات.
   - تسجيل الخروج.
   - قاعدة أساسية: كل اطلاع على ملف مريض يُسجَّل في سجل التدقيق.
2. **جلسة الدور:** يتبع كل متدرّب دليل دوره على حسابه.
3. **التمرين الجماعي:** رحلة المريض A كاملة، وكل دور ينفّذ خطوته بالترتيب، من الاستقبال حتى إغلاق السجل الطبي:
   1. الاستقبال
   2. التمريض
   3. الطبيب
   4. المختبر والأشعة
   5. الطبيب
   6. الصيدلية
   7. المحاسبة
   8. السجلات الطبية

   يتابع الجميع تقدم المريض في تبويب **Patient Journey** داخل زيارته.
4. **الاختبار العملي:** في آخر كل دليل قائمة مهام ينفّذها المتدرّب وحده، ويوقّع المدرّب عليها.

## السجل

احفظوا لكل متدرّب الاسم، والدور، وتاريخ الجلسة، ونتيجة الاختبار العملي، وتوقيع المدرّب. هذا السجل جزء من موافقة كل رئيس قسم (30.5).

## للمسؤول التقني

- **إنشاء بيئة التدريب:** نسخة ثالثة من الحزمتين بـ `COMPOSE_PROJECT_NAME` و`MEDPLUM_NETWORK` ومنافذ خاصة بها (انظر `DEPLOYMENT_ON_PREMISE.md`، القسم 8). تُملأ باستعادة نسخة احتياطية من بيانات اختبار وهمية، **وليس من الإنتاج أبداً**، ثم تُشغَّل التهيئة:

  ```bash
  cd services/hospital-api
  node --env-file=<seed.env> scripts/seed-training.mjs --training-environment
  ```

  المتغيرات المطلوبة موضّحة في رأس السكربت. يُنشئ حساب مدير التدريب وحساباً لكل دور ومرضى التمارين ومواعيد الغد، ويكتب ورقة الحسابات إلى `TRAINING_ACCOUNTS_FILE` خارج المستودع. يمكن إعادة تشغيله بأمان، فلا يكرر ما هو موجود.
- **بعد كل دورة تدريب:** أعيدوا الاستعادة والتهيئة، لتبدأ الدفعة التالية من البيانات نفسها.
