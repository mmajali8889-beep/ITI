| # | البند | الحالة | لماذا |

| 24.2 | فحص الأنواع للخادم بلا أخطاء + CI على GitHub (فحص أنواع، اختبارات، بناء الواجهة) | ✅ تم | يمنع دخول أخطاء جديدة بصمت |
| 24.3 | حفظ إلغاء الجلسات (logout) في مخزن دائم | ✅ تم | قائمة الجلسات الملغاة في الذاكرة؛ بعد إعادة تشغيل الخادم تعود الجلسة المسجَّل خروجها صالحة حتى انتهائها (8 ساعات، أو 30 يوماً مع "تذكرني"). الآن تُحفظ بصمة (SHA-256) لكل جلسة ملغاة في Medplum، فيبقى الخروج نافذاً بعد إعادة التشغيل ويصل لنسخ الخادم الأخرى خلال 60 ثانية |
| 24.4 | مخزن مشترك للقفل والجلسات | ✅ تم | كان القفل في ذاكرة نسخة واحدة. الآن: عدّادات محاولات الدخول الفاشلة في Medplum (مشتركة بين كل النسخ، تبقى بعد إعادة التشغيل، تحديث محمي بـ If-Match، واسم المستخدم مخزّن كبصمة SHA-256 فقط) مع تنظيف ساعي للسجلات المنتهية؛ إلغاء الجلسات كان مشتركاً منذ 24.3. اختُبر حياً: محاولتان على نسخة + ثلاث على أخرى = قفل على الاثنتين، ويبقى بعد إعادة التشغيل. استُخدم Medplum بدل Redis لتجنب خدمة واعتمادية جديدتين |
| 24.5 | تفعيل المصادقة وTLS على Orthanc | ✅ تم | يعمل حالياً بدون كلمة مرور، ومقيّد بالجهاز المحلي فقط. الآن: المصادقة مفعّلة بحساب خدمة للخادم، والمتصفح لا يحصل على كلمة مرور Orthanc أبداً؛ العارض يمر عبر وسيط (proxy) للقراءة فقط يشترط جلسة EHR وصلاحية radiology أو clinical. TLS يبقى ضمن 24.8 |
| 24.6 | إزالة دخول المطوّر `admin/admin` من بيئة الإنتاج والتأكد من `NODE_ENV=production` | ✅ تم | يعطَّل فقط عندما يكون `NODE_ENV=production`. الآن: لا يعمل إلا بتفعيل صريح (`AUTH_DEV_ADMIN_ENABLED=true`) وبيانات دخول محددة، بلا admin/admin افتراضي، والخادم يرفض التشغيل إذا فُعّل مع production |
| 24.7 | إدارة الأسرار (Vault أو Secret Manager) بدل ملفات `.env` | ✅ تم | الأسرار حالياً في ملفات محلية. الآن (تشغيل محلي في المستشفى): الأسرار ملفات بصلاحيات مقيّدة (Docker secrets) يقرؤها الخادم عبر `*_FILE`، وسكربت `generate-secrets.sh` ينشئها، والخادم يرفض التشغيل في production إذا كان إعداد حرج ناقصاً أو غير آمن. انظر docs/DEPLOYMENT_ON_PREMISE.md |
| 24.8 | HTTPS أمام الخادم والواجهة | ✅ تم | الكوكي يصبح `Secure` في الإنتاج فقط، ويحتاج HTTPS. الآن: وسيط Caddy يقدّم كل شيء على عنوان HTTPS واحد (تحويل HTTP، HSTS، ترويسات أمان)، بشهادة من قسم تقنية المعلومات أو CA داخلي، والخادم وOrthanc غير مكشوفين. اختُبر حياً: 18/18 فحصاً |
| 24.9 | معالجة 438 خطأ ESLint في الخادم، وإزالة `--fix` من سكربت `lint` | ✅ تم | لا يمكن إدخال lint إلى CI قبل ذلك، و`--fix` يعيد كتابة الملفات عند كل تشغيل. الآن: الخادم بلا أخطاء ESLint (كانت 7014: تنسيق Prettier في commit مستقل، وتصحيح 471 مشكلة كود بأنواع حقيقية بدل any)، وسكربت lint لا يعدّل الملفات (lint:fix منفصل)، وlint مفعّل في CI |
